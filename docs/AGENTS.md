# 프로젝트 개발 지침 및 아키텍처 인수인계 가이드 (AGENTS.md)

이 문서는 **'하곰이(Hagom)' 프로젝트**를 이어받아 개발하는 팀원 및 모든 AI 코딩 에이전트(Cursor, Claude Code, Windsurf 등)를 위한 **핵심 개발 지침서**이다.  
어떤 컴퓨터나 어떤 AI 도구를 사용하더라도 이 파일만 읽으면 프로젝트의 설계 의도, 임상 철학, 색상 체계, 인터랙션 원칙을 100% 이해하고 일관되게 개발할 수 있도록 작성되었다.

## 1. 🐻 프로젝트 개요 및 핵심 정체성
* **프로젝트명**: 하곰이 (Hagom)
* **목적**: 우울증, ADHD 등 정신건강의학과 환자를 위한 **비처벌적(Non-punitive) 복약 및 일상 루틴 케어 솔루션**

## 2. ⚖️ 절대 타협할 수 없는 5대 디자인 & 인터랙션 헌법

### ① 비처벌적 UX 헌법 (Non-punitive Policy)
* **연속 기록(Streak) 채찍질 절대 금지**:
  - ❌ *"연속 5일 기록이 깨졌어요! 분발하세요"* 같은 경고나 질책 문구는 환자에게 죄책감과 앱 이탈(Churn)을 유발하므로 전면 금지한다.
  - ⭕ 누적 실천 인정: *"이번 달에 벌써 15번이나 복용을 지켰어요!"*, *"절반이라도 챙긴 것이 소중한 한 걸음이에요!"*
* **과거 날짜 사후 기록 무조건 축하 (소급 축하 시스템)**:
  - 어제나 지난 날짜의 약/습관을 뒤늦게 체크해도 눈치를 주지 않고, *"언제든 기록해 준 것 자체가 대단해요! 👏"*라며 동일하게 기쁘게 축하한다.
* **접속 자체의 가치 인정**:
  - 약이나 습관을 하나도 하지 못했더라도, 앱을 켠 것만으로도 하곰이는 실망하지 않고 반갑게 맞이한다.

### ② 체크마크(✓, ✔) 배제 및 100% 색상 변화 방식 엄격 준수
* **버튼, 슬롯 칩, 뱃지 안에 체크 표시(`Icons.check`, `✓`)를 절대 넣지 않는다.**
* 완료 상태는 오직 **배경색(민트초록 `#EAF8F1`), 텍스트 색상(`AppColors.completedText #1B6B46`), 테두리 색상**의 정갈한 변화와 텍스트('완료')로만 표현한다.
* 터치 시 체크마크가 생기면서 버튼 크기가 들썩거리거나 레이아웃이 밀리는 현상을 원천 방지하기 위함이다.

### ③ 순수 한국어 표준어 사용 (개발자용 임시 'N' 표기 금지)
* 화면 버튼과 라벨에 `N시간마다`, `N일마다`, `주 N회` 같은 미완성 변수명을 쓰지 않는다.
* ⭕ **`시간 간격`**, **`며칠 간격`**, **`주간 횟수`** 등 상용 앱 표준 명칭을 사용한다.
* 입력창은 임의의 기본값(4시간, 2일 등)으로 채워두지 않고 **완전한 빈칸(`""`)을 기본으로 유지**하여 사용자가 원하는 숫자만 1초 만에 입력하게 한다.

### ④ 아날로그 시계판 다이얼 금지 ➔ 디지털 숫자 직접 입력
* 둥근 시계판 다이얼을 돌리는 방식은 환자의 입력 스트레스를 유발하므로 쓰지 않는다.
* 시(1~12)와 분(0~59)을 키보드로 즉시 입력하는 **`AppTimePicker.show(context)`** 공용 위젯을 전 화면에 일관되게 적용한다.

### ⑤ 팝업/모달의 네비게이션 독립성 (Nested Navigator)
* 모달 시트가 열려도 화면 맨 밑의 하단 네비게이션 바(`복약 | 습관 | 달력`)는 가려지지 않고 항상 떠 있어야 한다. 각 탭은 독립된 `Navigator`로 감싸져 있다.

## 4. 📅 달력 탭(Calendar) 3단계 시각화 알고리즘

복잡한 다중 색상을 배제하고, 환자와 의사가 0.5초 만에 상태를 파악할 수 있도록 **딱 3단계**로만 구분한다:

1. **🟢 전부 다 한 날 (복약 100% + 습관 100%)**:
   - 날짜 셀 전체를 **통 연초록 파스텔 틴트(`#E6F8F0`)**로 꽉 채우고 하단 바는 숨긴다.
   - 단, 일요일 날짜 숫자는 요일 구분을 위해 빨간색 글자색을 보존한다.
2. **🚨 처방약 누락일 (의사 처방 필수약 Focusin 미복용)**:
   - 임상적 안전 경고를 위해 **흰색 셀 + 하단 빨간색 캡슐 바(`#EF4444`, 2.5dp)**를 선명하게 띄운다.
3. **🟤 뭔가 덜 한 날 (일반약 또는 습관 미완료)**:
   - 처방약은 먹었으나 비타민 등 일반약을 덜 먹었거나 습관을 다 못 채운 날은 **흰색 셀 + 차분한 웜브라운 바(`#8B5E3C`)**로 안심시킨다.
4. **⚪ 아직 오지 않은 날짜 (미래)**:
   - 어떠한 바나 틴트도 없이 **완전한 순백색(White) 셀**로 깨끗하게 대기한다.

* **오늘 vs 과거 날짜의 아코디언 동작 분리**:
  - **오늘 날짜 터치 시**: 수정 버튼 없이 **단순 1줄 요약(조회 전용)**만 노출한다. (오늘은 각 탭에서 실천!)
  - **과거 날짜 터치 시**: **`수정하기`** 버튼이 나타나 아래로 펼쳐지며, 누르자마자 휙 바뀌지 않고 **"언제 복용하셨나요? (기억 안 남/모름 선택지 포함)"**, **"습관을 어떻게 실천하셨나요?"** 팝업을 거쳐 안전하게 기록한다.

## 5. 🏷️ 사용자 맞춤 버전 표기 공식 (Semantic Iteration System)

설정 화면(`settings_screen.dart`) 상단에 표기되는 버전은 다음 공식을 엄격히 따른다:

> **`v{A}.{B}.{C}`**
> 예시: **`v0.18.67`**

1. **`A` (메이저)**: 구글 플레이스토어 / 앱스토어 정식 대규모 배포 시에만 `1`로 승격 (현재 프로토타입은 `0`).
2. **`B` (마이너)**: Git 저장소에 커밋 & 푸시한 큰 단위의 누적 커밋 수 (`git rev-list --count HEAD`).
3. **`C` (패치/수정 카운트)**: **사용자와 대화하며 화면이나 코드를 자잘하게 수정한 총 누적 횟수**.
   - 사용자가 요청한 수정사항을 반영할 때마다 이 세 번째 숫자를 `+1`씩 올린다.
   - 사용자가 에뮬레이터 설정 화면을 열었을 때 **이 마지막 숫자가 올라간 것을 보고 수정이 정상 반영되었음을 확인**한다.

## 8. 🛠️ 작업 시 필수 주의사항 (AI 및 개발자 공통)
1. **🚨 모호한 요구사항 자의적 추측·대강 구현 절대 금지 (Ask Before Guessing)**:
   - 기획 의도나 UI 인터랙션, 임상 규칙이 조금이라도 모호하거나 명확하지 않은 부분이 있다면, **절대 "AI가 알아서 대강 그럴싸하게" 짐작하여 코드를 짜거나 수정하지 마라.**
   - 반드시 **"어떤 부분이 모호한지, 가능한 선택지는 무엇이 있는지"**를 사용자(또는 팀원)에게 구체적으로 질문하여 명확한 답변과 결정을 확인한 후 코딩에 착수해야 한다.
2. **📝 주요 기능/정책 변경 시 기획서·문서 동시 동기화 의무 (Keep Docs in Sync)**:
   - 단순한 폰트나 여백 수정이 아니라, **새로운 기능 추가, 복약/습관 인터랙션 정책 변경, 시각화 규칙 변경 등 의미 있는 큰 수정을 진행했을 경우**, 코드만 고치고 끝내지 말고 **반드시 `docs/PRD_기획명세서.md` 및 `docs/AI_활용_개발_프로세스_보고서.md`에도 해당 변경 사실과 의도를 즉시 함께 반영**해야 한다.
   - 코드는 최신인데 기획서는 과거에 멈춰있는 문서 불일치(Docs Rot)를 원천 차단한다.
3. **임의로 되돌리지 말 것**: 사용자와 검증을 마친 비처벌적 문구, 색상 체계, 아코디언 동작을 임의로 Material 3 기본값으로 덮어쓰지 않는다.
4. **이모티콘 남발 금지**: 텍스트 앞에 `🩺`, `🌱`, `🐾`, `✨` 같은 AI식 기호들을 기계적으로 붙이지 않는다.
5. **작업 완료 후 버전 동기화**: 기능을 수정했을 경우 `settings_screen.dart`의 마지막 버전 숫자(`C`)를 1 올려서 빌드한다.
6. **저장소 푸시 전 테스트**: `flutter analyze` 및 빌드 확인 후 의미 있는 단위로 커밋 메시지를 작성한다.
